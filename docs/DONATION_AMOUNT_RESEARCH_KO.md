# 치지직 후원 금액 자료형 추가 조사

확인일: 2026-09-10
범위: 공개 공식 문서, 공식 Session API의 직접 실측 자료, 관련 라이브러리 문서, 현재 LambLink 파서 재현.

## 결론

**공식 문서의 문자열 명세와 숫자를 받은 개발자의 공개 실측 기록이 불일치한다. LambLink가 숫자 금액에서 실패하는 것은 실제 파서로 재현했다.** 금액 자료형 불일치는 9월 9일 장애의 가장 유력한 원인이다. 당시 원문이 없어 해당 세 건의 직접 원인까지 확정하지는 않는다.

숫자와 문자열을 모두 정수 금액으로 안전하게 정규화하는 패치를 P0로 진행할 근거가 확보되었다. 정상 금액 형식을 하나로 단정하는 대신 두 입력을 지원하고, 잘못된 입력은 명시적으로 거부한다.

## 1. 출처별 근거

| 출처 | 확인 내용 | 근거의 성격과 한계 |
|---|---|---|
| [치지직 공식 Session 문서](https://chzzk.gitbook.io/chzzk/chzzk-api/session#message-event-subscribe-donation) | DONATION의 `payAmount` 타입이 `String` | 공식 명세. 조사일에 직접 열어 확인했으나 실제 패킷을 보장하는 자료는 아님 |
| [fi-xz의 Session API 실측 기록](https://gist.github.com/fi-xz/69ce1f35ca1b2318a2b410c0d5757e0f#donation) | CHAT·VIDEO 예시가 모두 숫자 금액이며 문서와 다르다고 명시 | 개발자의 직접 연결 관측. 네이버 공식 문서나 정정 공지는 아님 |
| [chzzkpy의 공식 API용 참조 문서](https://chzzkpy.yhs.kr/en/api.html#chzzkpy.message.Donation) | `Donation.pay_amount`가 `int` | 라이브러리 작성자의 문서. 파싱 후 모델일 수 있으므로 원시 JSON 타입의 독립적인 증명으로 취급하지 않음 |

실측 기록에는 2026-07-26 데이터 예시와 변경 이력이 있고, 페이지의 마지막 활동 표시는 2026-08-08이다. 이는 9월 9일 테스트보다 앞선 관측을 포함한다. 정확히 언제 문서와 서버 동작이 달라졌는지, 언제 숫자 타입이 처음 도입됐는지는 확인하지 못했다. 검색 수집일을 실제 관측일로 사용하지 않았다.

검색 결과에 같은 Gist의 댓글 링크·포크·복사본이 여러 번 나타났지만 이를 여러 독립 제보로 세지 않았다. `extras.payAmount`를 다루는 비공식 채팅 프로토콜 사례는 LambLink의 공식 Session API와 다르므로 직접 근거에서 제외했다.

개발센터 홈페이지는 공개 웹 열람에서 JavaScript 실행 안내만 반환했다. 공개 공식 API 문서는 직접 확인했으며, 로그인 전용 개발센터 화면이나 비공개 문의 답변을 확인했다고 주장하지 않는다. 조사 범위에서 네이버의 타입 불일치 공식 정정 공지는 찾지 못했다.

## 2. 현재 LambLink 코드로 재현

재현일: 2026-09-10. 환경: .NET 8.0.30, 현재 저장소의 Release Companion 빌드.

실행한 검증:

1. 실제 `ChzzkRealtimeClient` 인스턴스의 비공개 `DeserializeEventPayload<DonationEvent>`를 리플렉션으로 호출했다.
2. 동일한 가상 후원 데이터에서 `payAmount`만 문자열/숫자로 바꿨다.
3. CHAT와 VIDEO를 각각 비교했다.
4. 같은 `JsonSerializerDefaults.Web` 설정으로 역직렬화 예외를 별도 확인했다.

| 후원 종류 | 입력 | 실제 파서 결과 |
|---|---|---|
| CHAT | `"payAmount": "1000"` | 성공 |
| CHAT | `"payAmount": 1000` | null 반환, 후원 콜백 미진행 경로 |
| VIDEO | `"payAmount": "1000"` | 성공 |
| VIDEO | `"payAmount": 1000` | null 반환, 후원 콜백 미진행 경로 |

확인된 내부 오류:

```text
JsonException
Path: $.payAmount
Cannot get the value of a token type 'Number' as a string.
```

코드상 원인은 `DonationEvent.PayAmount`의 문자열 선언과 숫자→문자열 변환 처리 부재다. `DeserializeEventPayload`가 이 예외를 잡고 null을 반환하므로 운영 로그에는 세부 원인 대신 `DONATION parse failed`만 남는다.

테스트에는 빈 닉네임, 익명 후원자 표기, 추가 `emojis`·`eventSentAt` 필드도 포함했다. 문자열 금액에서는 성공했으므로 이 재현 입력의 실패를 결정한 변수는 금액 자료형이었다. 이 금액 1,000원은 비교 실험용 값이며, 스트리머의 실제 세 후원 금액을 알아낸 것이 아니다.

테스트는 임시 프로그램에서 현재 빌드의 코드를 호출했다. 치지직 로그인, 후원 결제, 게임 효과 실행을 하지 않았고 제품 파서를 수정하지 않았다.

## 3. 확신 수준 구분

- **확인됨:** 공식 문서는 문자열로 표기한다.
- **직접 실측 자료로 뒷받침됨:** 공식 Session API에서 숫자 금액을 받은 개발자 기록이 있다.
- **로컬 재현으로 확인됨:** 현재 LambLink는 숫자 금액에서 실패하고 문자열 금액에서는 성공한다.
- **강하게 지지되는 추론:** 9월 9일 세 건의 연속 파싱 실패가 이 결함 때문이었을 가능성이 높다.
- **미확정:** 그 세 패킷의 실제 자료형, 금액, 후원자, 테스트 알림 여부 및 정확한 예외 위치.

문서가 `String`이라고 해서 숫자 지원을 미룰 이유는 없다. 반대로 공개 실측이 숫자라고 해서 문자열 지원을 제거할 이유도 없다.

## 4. 패치 계획에 반영할 사항

1. `payAmount`의 숫자·문자열 입력을 모두 지원하고 내부에서는 양의 정수 금액으로 처리한다.
2. CHAT·VIDEO 각각 숫자/문자열 금액에 대한 회귀 테스트를 필수로 둔다.
3. null·소수·음수·범위 초과 등은 자동 보정하지 않고 실패 사유를 남긴다.
4. 로그에 수신 ID·시각·안전한 필드 경로·실제 JSON 자료형을 남겨 다음 장애는 원문 없이도 식별할 수 있게 한다.
5. 이중 인코딩된 이벤트 인자에 대한 테스트를 유지한다. 현재 코드는 Socket.IO 배열의 문자열 인자를 한 번 해제하므로, 이를 이번 금액 결함과 혼동하거나 모든 문자열을 반복 파싱하도록 바꾸지 않는다.
6. 수정 후 실제 치지직 수신에서 해석 성공→대기열 저장→게임 적용 ACK→후원 카드 표시를 별도로 검증한다.
