작성: 2026-09-10 KST. 상태: 소스 구현 및 자동 검증 완료. 이후 1.0.1 빌드·운영 CDN 배포 완료: [배포 기록](RELEASE_1.0.1_DEPLOYMENT_KO.md). 아래는 배포 전 검증 스냅샷이며 실환경 검증은 여전히 미완료다.

기준: [패치 계획서](DONATION_PATCH_PLAN_KO.md), [금액 자료형 조사](DONATION_AMOUNT_RESEARCH_KO.md).

## 구현

| 범위 | 변경 |

게임 효과 종류·금액 구간·사용자 규칙은 변경하지 않았다. 9월 9일 세 건의 원문이 없으므로 과거 패킷을 정확하게 재현한 것은 아니다.

## 자동 검증

후원 테스트 14개 그룹 통과:

1. CHAT/VIDEO 숫자·문자열 금액, 정수 상한, 익명 필드.
2. 잘못된 금액 거부 및 진단 입력값 노출 방지.
3. 이벤트 포장, 필수·선택 필드, 중복, 크기 제한.
4. 실제 수신 처리 메서드의 오류 후 정상 처리, 채팅·구독 파서 회귀.
5. 금액 구간·지역·비활성 규칙.
6. 대기열 재시작·중복 ID·저장 실패 일관성.
7. 손상된 대기열 원본 보존과 차단.
8. 결과 저장 실패 시 실행 중 중복 방지와 재시작 불확실 처리.
9. 적용 전 저장 실패 및 손상된 영수증 차단.
10. 보관 경계 이전의 알 수 없는 요청 거부, 보관된 결과 재사용.
11. 오버레이와 독립적인 이력 및 지연 응답의 상태 역행 방지.
12. Socket.IO 객체·문자열 인자 및 잘못된 프레임.
13. 영수증 v1 백업과 변환 후 결과 복구.
14. 미확인 표시 복구와 대기열 없는 미완료 기록의 불확실 처리.

Companion 참조 테스트 프로젝트와 Mod Release 빌드 성공. Mod 경고 0, 오류 0. `git diff --check` 오류 없음.

실제 서버·HTML을 사용하는 Chrome/Playwright 검증 통과: 서버보다 페이지 먼저 실행, 서버 재시작, HTTP 오류, 응답 정지, 페이지 재열기, 복구 후 카드 위치·크기, 미연결 중 표시 시간보다 오래 대기한 카드의 재연결 표시 및 개별 응답.

## 남은 검증과 제한

- 실제 치지직 알림 수신부터 게임 결과까지의 통합 검증. 실제 결제는 수행하지 않았다.
- 실게임의 마을·던전 전체 효과, 최소·최대 상태, 로딩·대화·일시정지·장면 이동.
- 실제 게임 프로세스의 ACK 유실·재접속·강제 종료. 저장소 테스트만으로 게임 전체의 정확히 한 번 적용을 보장한다고 주장하지 않는다.
- 실제 OBS의 로컬 파일 권한·실행 순서·Companion 재시작·추첨과 연속 후원. 일반 브라우저를 닫고 OBS 단독 검증해야 한다.
- 설치 패키지 교체 및 배포 버전 확정. 빌드 출력만 생성했으며 설치본 교체·릴리스 공개는 하지 않았다.

`PAGE_CONFIRMED`는 카드 DOM 표시 이후 페이지의 응답이며 실제 방송 프레임 증거가 아니다. 여러 페이지 중 어느 페이지의 응답이든 확인으로 처리한다. 브라우저별 세션 추적은 미구현이다. 확인 응답 유실·표시 중 연결 중단 시 안내가 다시 보일 수 있으나 게임 효과를 재실행하지 않는다.

## 저장 형식

Companion과 Mod를 함께 검증·교체한다. 프로토콜에 수신 시각과 결과 코드가 추가되었다. 이전 Companion은 수신 시각을 보내지 않아 영수증 보관 경계를 넘긴 새 Mod에서 요청이 거부될 수 있다.

Mod 영수증은 v2이며 v1 읽기 시 `.v1.bak`를 보존한다. 새 적용 기록은 현재 파일에 기록되므로 백업 단순 복원은 이후 적용 이력을 잃는다. 자동 롤백으로 사용하지 않는다. 구버전에서 이미 제거한 영수증은 복원할 수 없다. 시계 변경이나 늦게 도착한 과거 요청은 `HISTORY_EXPIRED`로 보수적으로 거부될 수 있다.

손상 파일을 임의 삭제해 재전송하지 않는다. 원본과 게임 상태를 확인해야 한다. 자동 수리·수동 유료 이벤트 재실행 도구는 포함하지 않았다. 신규 운영 이력은 이름·메시지를 저장하지 않지만 기존 대기열·영수증에는 게임 처리용 후원자 정보가 남을 수 있다.

## 테스트 실행

저장소 루트에서 실행한다.

```powershell
dotnet run --project tests/LambLink.DonationTests/LambLink.DonationTests.csproj -c Release
dotnet build src/LambLink.Mod/LambLink.Mod.csproj --no-restore -c Release
dotnet build tests/LambLink.OverlayRecoveryTests/LambLink.OverlayRecoveryTests.csproj -c Release
node tests/LambLink.OverlayRecoveryTests/recovery.cjs
```

브라우저 테스트는 Node의 `playwright` 모듈과 Windows 기본 경로의 Chrome이 필요하다. 환경에 따라 `NODE_PATH`를 지정한다. 테스트는 임시 파일을 생성·정리하며 실제 게임 저장 파일을 사용하지 않는다.
